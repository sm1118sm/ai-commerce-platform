# 사용자 행동 기반 AI 추천·UI/UX 개인화 설계

## 1. 목표와 원칙

StylePick AI의 개인화는 상품 순위만 바꾸는 것이 아니라 사용자가 자주 하는
일을 더 빠르게 완료하도록 홈 화면의 콘텐츠 모듈 순서를 조정한다.

반드시 지킬 원칙:

- 로고, 전체 검색, 카테고리, 찜, 장바구니, 마이페이지 위치는 고정한다.
- 홈 화면의 추천 섹션 순서와 섹션 내부 상품만 개인화한다.
- 한두 번의 클릭으로 화면을 급격히 바꾸지 않는다.
- 사용자가 개인화 이유를 확인하고 초기화하거나 끌 수 있어야 한다.
- 비밀번호, 전화번호 등 추천과 무관한 개인정보는 절대 모델에 넣지 않는다.
- 높은 클릭률보다 구매 만족, 다양성, 품절 방지, 오류 없는 사용을 우선한다.

## 1.1 이커머스형 비주얼·정보 구조

브랜드 빌더 서비스의 랜딩 페이지에서 보이는 넓은 여백, 짧고 강한 문구,
명확한 CTA, 반복 가능한 카드 시스템, 신뢰 지표와 촘촘한 푸터 구성을
참고한다. 다만 템플릿·요금·전문가 찾기 같은 사이트 제작 서비스 메뉴는
StylePick AI의 목적과 맞지 않으므로 복제하지 않는다.

### 고정 글로벌 헤더

1. StylePick AI 로고
2. 상품 통합 검색
3. 카테고리
4. AI 추천
5. 찜
6. 장바구니
7. 마이페이지

PC에서는 검색을 헤더 중앙의 핵심 기능으로 노출한다. 모바일에서는 로고,
검색, 장바구니를 우선 표시하고 나머지는 하단 내비게이션 또는 메뉴로
정리한다. 이 위치는 개인화로 바꾸지 않는다.

### 반응형 브레이크포인트

- `901px 이상`: 최대 1280px 콘텐츠, 3~4열 상품 진열, 2단 히어로
- `641~900px`: 히어로 1단 전환, 필터 재배치, 2열 중심 상품 진열
- `640px 이하`: 1열 상품 진열, 하단 고정 핵심 탭, 44px 이상 터치 버튼

모바일에서는 가로 스크롤이 생기지 않게 카드와 필터를 세로로 쌓는다. 핵심
탭은 엄지손가락으로 접근하기 쉬운 하단에 두고, 본문 하단 여백을 확보해
마지막 상품과 주문 버튼을 가리지 않게 한다. PC와 모바일 모두 같은 기능과
가격·재고 정보를 제공하며 화면이 작다는 이유로 핵심 구매 정보를 숨기지
않는다.

### 기본 홈 화면

1. 사용 목적이 즉시 보이는 개인화 히어로와 `AI 추천받기` CTA
2. 아이콘형 카테고리 퀵메뉴
3. `OO님을 위한 추천` 상품 캐러셀
4. 지금 많이 보는 상품
5. 신상품과 시즌 큐레이션
6. 취향을 넓히는 브랜드·카테고리 스토리
7. 배송·반품·고객지원 신뢰 영역

히어로는 가입 유도만 반복하지 않고 로그인 사용자의 최근 의도에 맞춰
문구와 추천 진입점만 바꾼다. 상품 가격, 배송 조건, 재고와 추천 이유는
시각적으로 구분하고 허위 할인·허위 구매 건수·검증되지 않은 성장 수치는
표시하지 않는다.

### 상품 카드와 상세

- 실제 상품 이미지를 가장 크게 배치하고 브랜드, 상품명, 가격 순으로 읽힌다.
- 찜과 장바구니는 카드에서 즉시 실행할 수 있지만 상세 보기와 혼동되지 않는다.
- 품절, 재고 부족, 신상품 같은 상태는 색상만이 아니라 텍스트로도 표시한다.
- 상세 화면에는 이미지, 핵심 혜택, 옵션, 배송·반품, 리뷰, 연관 추천을 둔다.
- 추천 카드는 `최근 검색과 비슷해요`처럼 실제 점수 요인에 근거한 이유를 표시한다.

### 신뢰와 푸터

- 배송 안내, 교환·반품, FAQ, 고객지원, 개인정보처리방침, 이용약관을 제공한다.
- 데모 단계에서는 실제 결제가 아님을 주문 CTA 주변에 명확히 표시한다.
- 외부 서비스의 고객 수·거래액·인증 같은 수치를 StylePick AI의 실적으로
  오인할 수 있게 사용하지 않는다.

## 2. 수집할 행동 데이터

### 검색 행동

- 검색어 원문과 정규화 검색어
- 검색 시각과 세션
- 검색 결과 개수
- 사용한 카테고리·가격·정렬 필터
- 검색 결과에서 클릭한 상품과 노출 순위
- 검색 후 찜·장바구니·구매 여부
- 결과가 0개였는지 여부

검색어는 그대로 장기간 보관하지 않고 추천용 키워드·카테고리 특징으로
집계한다. 이메일, 전화번호, 주소처럼 보이는 검색 문자열은 저장 전에
마스킹하거나 버린다.

### 상품 행동

- 상품 카드 노출, 위치, 추천 섹션
- 상품 클릭과 상세 페이지 진입
- 체류 시간과 이미지·상세 정보 확인
- 찜 추가·해제
- 장바구니 추가·제거와 수량
- 구매와 반복 구매
- 품절 상품 또는 추천 숨기기

### UI 행동

- 자주 방문하는 탭과 카테고리
- 홈 화면에서 실제로 클릭한 섹션
- 필터·정렬 사용 빈도
- 모바일·PC 구분
- 개인화 섹션 숨기기·고정하기·초기화

스크롤만 했다는 이유로 강한 관심으로 판단하지 않는다. 노출 시간이 너무
짧거나 백그라운드 탭인 경우 노출 데이터에서 제외한다.

## 3. 사용자 취향 프로필

사용자 프로필은 장기 취향과 단기 의도를 분리한다.

### 장기 프로필

- 최근 90일 카테고리 선호도
- 자주 검색한 의미 주제
- 주로 선택하는 가격대
- 브랜드·색상·사용 상황 선호
- 구매와 반복 구매 이력

### 단기 세션 프로필

- 현재 세션의 최근 검색어
- 최근 본 상품 5~20개
- 현재 적용한 카테고리와 가격 필터
- 방금 찜하거나 장바구니에 담은 상품

최종 사용자 벡터의 시작 비율:

```text
사용자 의도 = 장기 취향 0.60 + 최근 7일 행동 0.25 + 현재 세션 0.15
```

현재 세션에서 검색어를 명확하게 입력한 경우에는 단기 의도 비율을 높인다.
로그아웃 상태는 익명 세션 데이터만 사용하고 로그인 후 합칠지는 사용자에게
알린다.

## 4. 검색 빈도에 따른 홈 UI 배치

개인화 전에 최소 5회의 유효 행동 또는 3회의 전환 행동을 요구한다. 데이터가
부족하면 기본 홈 화면을 유지한다.

### 검색 중심 사용자

판단:

- 방문 세션의 절반 이상에서 검색 사용
- 검색 후 상품 클릭 또는 찜 전환이 반복됨

배치:

1. 큰 통합 검색창
2. 최근 검색과 자주 찾는 주제
3. 이전 검색과 의미가 비슷한 추천
4. 검색 결과가 없었던 항목의 대체 상품
5. 트렌드와 새로운 카테고리 탐색

### 카테고리 집중 사용자

판단:

- 특정 카테고리 행동 점수가 전체의 50% 이상
- 서로 다른 날에 같은 카테고리를 반복 방문

배치:

1. 선호 카테고리 신상품
2. 최근 본 상품과 유사한 상품
3. 선호 카테고리의 예산 내 인기 상품
4. 연관 카테고리 탐색
5. 전체 트렌드

### 가격·할인 중심 사용자

판단:

- 가격 필터 사용 빈도가 높음
- 낮은 가격순 정렬이나 특정 예산 구간 선택이 반복됨

배치:

1. 자주 선택한 예산 범위 내 추천
2. 가격 대비 평점이 높은 상품
3. 찜 상품 가격 변화
4. 예산보다 조금 높은 대안

실제 할인이 없는 데모 상품에 허위 할인율을 표시하지 않는다.

### 재구매·목적형 사용자

판단:

- 식품·소모품 구매 주기가 반복됨
- 비슷한 검색과 구매가 일정 간격으로 발생

배치:

1. 재구매 예상 상품
2. 이전 구매의 대체·보완 상품
3. 같은 목적의 새로운 상품

### 탐색형 신규 사용자

배치:

1. 관심 카테고리 선택
2. 예산 설정
3. 전체 인기와 최근 트렌드
4. 서로 다른 카테고리의 대표 상품
5. 자연어 추천 검색 예시

## 5. 추천 파이프라인

```text
행동 이벤트
  → 개인정보 제거·정규화
  → 사용자 장기/단기 특징 집계
  → 후보 생성
  → 개인화 랭킹
  → 다양성·재고·중복 재정렬
  → 설명과 모델 버전 저장
  → 홈 모듈 및 상품 카드 노출
```

### 후보 생성

- E5 의미 유사 상품
- 관심 카테고리 상품
- 찜·구매 상품과 유사한 상품
- 최근 사용자 트렌드
- 향후 협업 필터링 후보

각 방법에서 상위 20~100개를 가져와 하나의 후보군으로 합친다.

### 랭킹

초기에는 현재의 가중치 기반 하이브리드 점수를 유지한다. 행동 데이터가
쌓이면 클릭·찜·장바구니·구매를 정답으로 사용하는 Learning-to-Rank 모델을
후보로 실험한다.

가능한 특징:

- E5 콘텐츠 유사도
- 사용자·상품 카테고리 일치도
- 검색어·상품 의미 유사도
- 예산 차이
- 최근 행동과 경과 시간
- 상품 평점·인기도·재고
- 동일 상품 노출 횟수
- 추천 섹션과 노출 위치

### 재정렬과 탐색

- 70%: 현재 선호와 가장 관련 높은 상품
- 20%: 연관 카테고리와 새로운 상품
- 10%: 무작위가 아닌 품질 기준 탐색 후보

한 카테고리·브랜드가 화면을 독점하지 않도록 상한을 둔다. 이미 구매한
내구재, 반복적으로 숨긴 상품, 품절 상품은 제외한다.

## 6. 홈 화면 모듈 순위

상품 랭커와 별도로 모듈 랭커를 둔다.

모듈 후보:

- 자연어 AI 검색
- 최근 본 상품
- 자주 검색한 주제
- 관심 카테고리 신상품
- 예산 내 추천
- 찜 상품과 유사한 상품
- 장바구니 연관 상품
- 재구매 예상 상품
- 최근 트렌드
- 새로운 카테고리 탐색

초기 모듈 점수:

```text
모듈 점수 =
  최근 30일 클릭률 0.25
  + 찜·장바구니 전환율 0.30
  + 최근 사용 빈도 0.20
  + 현재 세션 관련도 0.15
  + 다양성 보너스 0.10
```

모듈 순서는 세션 중간에 갑자기 바꾸지 않고 다음 방문부터 적용한다. 사용자가
고정한 모듈은 자동으로 이동하지 않는다.

## 7. 필요한 DB 구조

### recommendation_impressions

- `impression_id`
- `user_id` 또는 익명 `session_id`
- `product_id`
- `module_name`
- `position`
- `model_version`
- `recommendation_score`
- `reason_code`
- `created_at`

### recommendation_interactions

- `impression_id`
- `action_type`
- `created_at`

기존 `behavior_logs`와 연결해 추천 노출 이후 클릭·찜·장바구니·구매 전환을
계산한다.

### user_feature_snapshots

- `user_id`
- 장기 카테고리·가격·검색 주제 특징 JSON
- 단기 특징 JSON
- 집계 기준 시각
- 특징 버전

실시간 특징은 Redis 같은 별도 시스템 없이 MySQL과 짧은 캐시로 시작하고,
트래픽이 늘 때만 분리한다.

## 8. 정확도와 UI 평가

### 오프라인 추천 평가

- Precision@K, Recall@K, NDCG@K, MRR
- 카테고리·브랜드 다양성
- 신규 상품 노출률
- 품절·이미 구매한 상품 노출률

### 온라인 행동 평가

- 추천 클릭률
- 찜·장바구니·구매 전환율
- 검색 후 첫 유효 클릭까지 걸린 시간
- 검색 결과 없음 비율
- 추천 숨기기와 바로 이탈 비율

### UI/UX 평가

- 원하는 상품까지 클릭 수
- 작업 완료 시간
- 모바일에서의 이탈률
- 개인화 모듈별 참여율
- 화면 배치가 바뀌어 혼란스럽다는 피드백

A/B 테스트는 사용자 단위로 고정 배정하고 한 번에 한 가지 변화만 비교한다.
클릭률이 높아도 구매 취소, 숨기기, 이탈이 나빠지면 배포하지 않는다.

## 9. 개인정보와 사용자 통제

- 개인화 추천 사용 여부 토글
- 최근 검색 삭제
- 추천 취향 초기화
- 특정 상품·카테고리 덜 보기
- `이 상품이 추천된 이유` 표시
- 회원 탈퇴 시 특징·노출·상호작용 데이터 삭제
- 행동 로그 보관 기간 설정
- 민감한 검색어 자동 마스킹

성별, 나이, 전화번호 같은 민감하거나 추천에 불필요한 값으로 가격과 상품
노출을 차별하지 않는다.

## 10. 구현 우선순위

### P0 — 정확한 측정을 위한 데이터

- [ ] 추천 노출 ID, 위치, 모델 버전 저장
- [ ] 추천 클릭과 후속 전환을 노출 ID에 연결
- [ ] 검색어 정규화와 개인정보 마스킹
- [ ] 검색 결과 없음 이벤트 저장

- [ ] 자주 검색한 주제와 가격대 계산
- [ ] 사용자 유형별 홈 모듈 규칙 구현
