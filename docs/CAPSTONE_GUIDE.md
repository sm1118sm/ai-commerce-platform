# StylePick AI 캡스톤 완성 가이드

## 1. 프로젝트 제목 후보 5개

1. **StylePick AI** — 설명 가능한 개인화 쇼핑 큐레이터
2. **PickMate** — 취향을 이해하는 AI 상품 추천 서비스
3. **CartMuse** — 관심 상품에서 발견하는 다음 쇼핑 아이템
4. **MyFit Market** — 예산과 관심사를 반영하는 맞춤형 마켓
5. **ReasonPick** — 추천 이유를 알려주는 투명한 AI 쇼핑몰

최종 이름은 짧고 발표하기 쉬운 **StylePick AI**로 선정한다.

## 2. 프로젝트 한 줄 설명

사용자의 관심 카테고리, 찜 상품, 예산을 분석해 관련 상품과 추천 이유를
제공하는 TF-IDF 기반 개인화 이커머스 웹앱이다.

## 3. 해결하려는 문제

일반적인 소형 쇼핑몰의 상품 목록은 모든 사용자에게 동일하다. 사용자는
자신에게 필요한 상품을 찾기 위해 검색과 필터를 반복해야 하고, 추천 근거를
알 수 없는 경우 결과를 신뢰하기 어렵다. StylePick AI는 적은 사용자
데이터만으로 취향을 반영하고 추천 이유까지 보여줘 탐색 부담을 줄인다.

## 4. 핵심 차별점

- 회원별 관심사와 클릭·찜·장바구니·구매 행동이 분리되어 추천에 반영된다.
- 추천 점수 구성 요소와 자연어 추천 이유를 함께 보여준다.
- 외부 유료 API 없이 로컬에서 빠르고 안정적으로 실행된다.
- 사용자 정보가 없는 경우 인기도·예산 기반 콜드 스타트를 제공한다.

## 7. 기술 스택 비교와 최종 선정

| 항목 | Streamlit + Python + MySQL | React + FastAPI + MySQL |
|---|---:|---:|
| 화면 개발 속도 | 매우 빠름 | 느림 |
| 추천 모델 연결 | 직접 연결 | API 개발 필요 |

| 3일 완성 위험 | 낮음 | 중간~높음 |

한 언어와 한 프로세스로 전 기능을 구현해 시연 안정성을 확보한다. 3일
프로젝트에서는 React의 디자인 이점보다 기능 연결과 오류 수정 시간이 더

## 11. 사용자 관심 데이터 구조

화면 상태는 `st.session_state`로 즉시 반영하고, 실제 데이터는 MySQL의
`stylepick` 데이터베이스에 저장한다.

```python
{
    "nickname": "이상민",
    "interests": ["전자기기", "스포츠"],
    "budget": (20000, 150000),
    "favorites": {"P001", "P024"},
    "cart": {"P002": 1, "P028": 2},
    "last_order": None
}
```

PBKDF2 비밀번호 해시를 사용하는 `users`와 `user_preferences`, 회원별
`user_favorites`, `user_cart`, `behavior_logs`, `user_orders`,
`order_items` 테이블을 사용한다. 여러 회원의 데이터가 서로 분리된다.

## 12. 추천 알고리즘 동작 과정

1. 상품명, 카테고리, 설명을 하나의 텍스트로 합친다.
2. TF-IDF가 전체 상품 말뭉치의 단어·2-gram 중요도를 학습한다.
3. 관심 카테고리와 찜 상품으로 명시적 취향 벡터를 만든다.
4. 최근 90일 클릭·찜·장바구니·구매에 행동·최근성 가중치를 적용한다.
5. 사용자 취향 및 행동과 모든 상품의 코사인 유사도를 계산한다.
6. 관심 카테고리, 예산, 최근 7일 전체 트렌드를 결합한다.
7. 이미 찜·구매했거나 품절인 상품을 제외하고 카테고리 다양성을 적용한다.

TF-IDF의 `fit_transform`이 어휘와 IDF 가중치를 데이터에서 학습하는 AI/ML
부분이다. 예산·카테고리 가산점과 추천 문장 조립은 일반 규칙 기반 로직이다.

## 13. 추천 점수 계산 공식

개인화 정보가 있을 때:

```text
최종 점수 =
  0.35 × TF-IDF 콘텐츠 유사도
  + 0.20 × 관심 카테고리 일치
  + 0.20 × 최근 행동 유사도
  + 0.10 × 예산 범위 일치
  + 0.15 × 최근 7일 트렌드
```

초기 사용자일 때:

```text
콜드 스타트 점수 =
  0.45 × 최근 트렌드
  + 0.25 × 예산 범위 일치
  + 0.20 × 누적 인기도
  + 0.10 × 평점
```

가중치는 모델 학습 결과가 아니라 MVP의 설명 가능한 비즈니스 규칙이다.
행동 가중치는 클릭 1, 찜 4, 장바구니 5, 구매 8점이며 최근 1일 100%,
7일 80%, 30일 50%, 이후 20%의 최근성 가중치를 적용한다.

## 14. 추천 이유 생성

- 카테고리 일치: `관심 카테고리인 전자기기 상품입니다.`
- 찜 기반 텍스트 유사도 0.08 이상: `찜한 상품과 이름·설명이 유사합니다.`
- 행동 기반 유사도: `최근 클릭·장바구니 상품과 특징이 유사합니다.`
- 트렌드: `최근 사용자들의 관심이 높은 상품입니다.`
- 예산 범위 일치: `설정한 예산 범위에 포함됩니다.`
- 조건이 없을 때: `현재 인기 상품 중 선호 조건과 가장 가깝습니다.`

추천 이유는 생성형 AI가 아니라 실제 점수 구성 요소를 문장으로 변환한다.
따라서 환각이 없고 오프라인에서도 항상 같은 결과를 낸다.

## 20. 오류가 발생했을 때 확인할 사항

- `ModuleNotFoundError`: 가상환경 활성화와 `pip install` 여부 확인
- CSV 오류: 실행 위치와 `data/products.csv` 존재 여부 확인
- 포트 충돌: `streamlit run app.py --server.port 8502`
- 추천 결과 없음: 가격 범위를 넓히거나 필터 초기화
- 상태 복구 실패: `DATABASE_URL`과 MySQL 접속 상태 확인
- 한글 깨짐: CSV를 UTF-8로 저장
- 배포 실패: 저장소 루트와 `requirements.txt` 위치 확인

## 24. 교수님 예상 질문과 답변

### 왜 딥러닝을 사용하지 않았나요?

상품이 30개이고 학습 로그가 없는 상황에서 임베딩 모델은 설치 용량과 네트워크
의존성만 늘릴 수 있습니다. TF-IDF는 작은 데이터에 적합하고 결과를 설명할
수 있어 3일 MVP에 더 타당합니다.

### 이 기능을 AI라고 할 수 있나요?

TF-IDF는 상품 말뭉치에서 어휘와 역문서 빈도 가중치를 학습하고 상품·사용자를
벡터 공간에 표현합니다. 코사인 유사도로 새로운 사용자 프로필에 대한 추천을
계산하므로 콘텐츠 기반 머신러닝 추천입니다.

### 추천 정확도는 어떻게 평가했나요?

실사용자 정답 데이터가 없어 오프라인 정확도 대신 카테고리 적합성, 찜 제외,
설명 일치, 점수 범위를 자동 테스트했습니다. 실제 서비스에서는 클릭률,
찜 전환율, 구매 전환율과 A/B 테스트가 필요합니다.

### 개인정보는 어디에 저장하나요?

이메일, PBKDF2 비밀번호 해시, 닉네임과 취향은 MySQL에 저장됩니다.
비밀번호 원문은 저장하지 않습니다.

### 콜드 스타트는 어떻게 해결했나요?

취향 데이터가 없을 때 트렌드 45%, 예산 25%, 누적 인기도 20%, 평점 10%로
추천합니다. 관심 카테고리나 행동이 생기는 즉시 개인화 공식으로 전환됩니다.

### 추천 이유는 생성형 AI인가요?

아닙니다. 실제 점수 근거를 규칙으로 문장화합니다. 시연 안정성과 설명
정확성을 위해 생성형 모델을 사용하지 않았습니다.

### 실제 서비스로 확장하려면 무엇이 필요한가요?

외부 운영 DB, 개인정보 동의·암호화 키 관리, 실제 결제 API, 이메일 인증,
추천 품질 모니터링이 필요합니다.

## 25. 한계와 향후 발전

- 샘플 상품 30개이므로 실제 추천 품질을 일반화할 수 없다.
- 실제 운영 규모의 행동 로그가 없어 협업 필터링과 정량 정확도 평가가 없다.
- 현재는 이메일 인증과 비밀번호 재설정을 지원하지 않는다.
- 수동 가중치는 실제 로그를 이용해 학습하거나 A/B 테스트해야 한다.
- 상품 이미지는 네트워크 안정성을 위해 이모지로 대체했다.

향후에는 implicit feedback 추천, 사전 학습 문장 임베딩 비교, A/B 테스트
대시보드, MySQL 운영 자동화와 실제 상품 API 연동 순으로 발전시킨다.
