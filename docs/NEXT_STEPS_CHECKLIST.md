# StylePick AI 다음 작업 순서 체크리스트

이 문서는 현재 MySQL 회원 시스템과 E5 1차 추천 모델 이후의 작업 순서를
정의한다. 각 단계의 완료 조건을 만족한 뒤 다음 단계로 이동한다. 모든 작업은
기능 브랜치 → 자동 테스트 → Pull Request → CI → merge 순서로 진행한다.

## 현재 완료 상태

- [x] MySQL 8 회원·상품·행동·주문 저장 구조
- [x] 이메일·닉네임·전화번호 중복 가입 차단
- [x] 비밀번호 해시 저장과 회원 탈퇴 데이터 삭제
- [x] E5 한국어 의미 추천 1차 모델
- [x] TF-IDF 대비 E5 고정 벤치마크
- [x] Docker 전체 테스트 19개와 GitHub CI
- [x] PR #1 생성·검증·merge

## 1단계 — 추천 정확도 평가 기반 확대

가장 먼저 진행한다. 평가 데이터가 작으면 더 큰 모델을 사용해도 실제로
좋아졌는지 알 수 없다.

- [x] 한국어 쇼핑 의도 평가 문장 초안을 12개에서 222개로 확대
- [ ] 210개 신규 초안을 사람 검수해 승인 데이터로 전환
- [x] 상품별로 자연어 검색 의도·동의어·사용 상황 초안 작성
- [ ] 한 문장에 관련 상품을 1개가 아닌 관련도 등급으로 표시
- [ ] 평가 데이터를 학습·검증·최종 테스트 세트로 분리
- [ ] 최종 테스트 세트는 모델 선택과 가중치 조정에 사용하지 않기
- [ ] 인기순, TF-IDF, E5 결과를 같은 데이터에서 비교
- [ ] 카테고리별 Precision@K, Recall@K, NDCG@K, MRR 측정
- [ ] 실패 검색어와 결과 없음 사례를 별도 보고서로 저장

완료 조건:

- 재실행 가능한 평가 스크립트가 존재한다.
- 카테고리별 표본 수와 전체 표본 수가 보고서에 표시된다.
- 모델 변경 전후 지표를 같은 테스트 세트에서 비교할 수 있다.

## 2단계 — 상품 데이터 품질 향상

추천 모델은 상품 설명에 없는 특징을 추측할 수 없으므로 상품 정보를 먼저
풍부하게 만든다.

- [ ] 상품 수를 시연에 필요한 규모로 확대
- [x] `brand`, `tags` 필드 추가 및 정리
- [ ] `color`, `material`, `use_case`를 구조화된 필드로 추가
- [ ] 대상 사용자, 계절, 장소, 용도 태그 추가
- [x] 상품명·설명·필수 메타데이터 기본 검사
- [ ] 실제 이미지, 가격, 재고, 판매 상태 연결
- [ ] 품절·비활성 상품을 추천 후보에서 제외
- [ ] 상품 데이터 변경 시 임베딩을 다시 생성하는 작업 추가

완료 조건:

- 모든 활성 상품에 필수 메타데이터가 존재한다.
- 데이터 검사 테스트가 CI에서 자동 실행된다.

## 3단계 — 2단계 추천 파이프라인

빠른 후보 검색과 느리지만 정확한 재정렬을 분리한다.

### 후보 검색

- [ ] E5로 자연어 의도와 유사한 상품 Top-30~50 생성
- [ ] 관심 카테고리·찜·최근 행동 후보 추가
- [ ] 인기·트렌드·신상품 후보 추가
- [ ] 후보 중복 제거와 품절·구매 완료 필터

### 정밀 재정렬

- [ ] 다국어 Cross-Encoder 재정렬 모델을 선택 사항으로 구현
- [ ] 검색 문장과 상품 설명을 함께 입력해 관련도 계산
- [ ] E5 점수, 재정렬 점수, 예산, 평점, 행동 점수 결합
- [ ] 부정 행동 상품 점수 감소
- [ ] 카테고리·브랜드 다양성 재정렬
- [ ] 추천 이유가 실제 점수 요인과 일치하는지 검사
- [ ] 모델을 켜고 끌 수 있는 기능 플래그 추가

완료 조건:

- 재정렬 모델이 고정 테스트 세트의 NDCG를 기준 모델보다 개선한다.
- CPU 환경의 추천 응답시간 p95가 목표 범위 안에 있다.
- 개선이 없거나 너무 느리면 E5 단독 모델로 자동 복귀할 수 있다.

## 4단계 — 추천 노출·클릭·전환 로그

실제 정확도를 개선하려면 추천 결과와 후속 행동을 연결해야 한다.

- [ ] `recommendation_impressions` 테이블 추가
- [ ] 노출 ID, 사용자, 상품, 위치, 모듈, 점수 저장
- [ ] 모델 이름·버전·가중치 버전 저장
- [ ] 추천 클릭을 노출 ID와 연결
- [ ] 찜·장바구니·구매 전환을 노출 ID와 연결
- [ ] 검색 결과 없음과 추천 숨기기 이벤트 저장
- [ ] 이메일·전화번호처럼 보이는 검색어 마스킹
- [ ] 회원 탈퇴 시 추천 로그 삭제
- [ ] 로그 보관 기간과 정리 작업 정의

완료 조건:

- 한 추천 노출에서 클릭과 구매까지 추적할 수 있다.
- 비밀번호와 불필요한 개인정보가 로그에 포함되지 않는다.

## 5단계 — 사용자별 장기·단기 취향

- [ ] 최근 90일 장기 카테고리·가격·검색 주제 프로필
- [ ] 최근 7일 행동 프로필
- [ ] 현재 세션 검색·클릭 프로필
- [ ] 행동 최근성 감쇠 적용
- [ ] 반복 노출과 반복 숨기기 반영
- [ ] 신규 사용자 콜드 스타트 유지
- [ ] 개인화 사용 중지와 취향 초기화 기능

완료 조건:

- 서로 다른 두 사용자의 추천 결과가 실제 행동에 맞게 달라진다.
- 한 번의 우연한 클릭으로 전체 추천이 급격하게 바뀌지 않는다.

## 6단계 — 실제 데이터 학습

충분한 데이터가 쌓이기 전에는 복잡한 학습 모델을 억지로 적용하지 않는다.

- [ ] 사용자·상품 상호작용 수와 데이터 밀도 모니터링
- [ ] 클릭보다 찜·장바구니·구매에 더 높은 정답 가중치 부여
- [ ] 시간순으로 학습·검증 데이터 분리
- [ ] 협업 필터링 후보 모델 실험
- [ ] Learning-to-Rank 후보 모델 실험
- [ ] 위치 편향과 인기 상품 편향 보정
- [ ] 모델 버전별 오프라인 성능 기록
- [ ] 기존 모델보다 개선된 경우에만 기본 모델로 승격

학습 도입 판단 기준:

- 실제 사용자 100명 이상
- 유효 행동 로그 5,000건 이상
- 사용자당·상품당 여러 개의 상호작용 존재
